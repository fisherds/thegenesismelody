# Genesis Melody — src/ Workflow

## What this folder is

Supporting data and scripts for `public/index.html`, the main article page.

### Key files

- `TheGenesisMelody_sentences.json` — **our primary source of truth** for sentence-level audio cues. Originally generated by Whisper, now maintained by hand. Each sentence has `id`, `start`, `end`, and `text`.
- `TheGenesisMelody_words.json` — word-level timestamps generated by Whisper. Regenerated from audio when audio is re-recorded; do not edit by hand.

---

## The sentence ID system

Each sentence in `TheGenesisMelody_sentences.json` has a stable `id` field (e.g. `"id": "a1b2c3d4"`). The corresponding element in `public/index.html` carries a matching `data-sentence-id` attribute on the element that wraps the `gm-cue` span (or on the `gm-cue` span's parent block element).

**Why:** When audio is re-recorded and Whisper produces a new `TheGenesisMelody_words.json`, we can run a Python script to re-sync timestamps in `TheGenesisMelody_sentences.json` by fuzzy-matching text, then propagate updated timestamps into the HTML by matching `data-sentence-id` — no fragile line-number alignment needed.

### JSON format

```json
{
  "id": "a1b2c3d4",
  "start": 4702,
  "end": 4703,
  "text": "Your next steps."
}
```

### HTML format

The `data-sentence-id` goes on the **block element** that contains the `gm-cue` span:

```html
<h2 class="c45" data-sentence-id="a1b2c3d4" data-t-end="4703" data-t-start="4702" id="your-next-steps">
  <span class="gm-cue" data-t-end="4703" data-t-start="4702">
    <span class="c42 c44">Your Next Steps</span>
  </span>
</h2>
```

---

## Re-sync workflow (when audio is re-recorded)

1. Run Whisper on the new audio → produces a new `TheGenesisMelody_words.json`.
2. Run `src/resync_sentences.py` — fuzzy-matches new word timestamps to sentences in `TheGenesisMelody_sentences.json` by text similarity, updates `start`/`end` in place, preserves `id` fields.
3. Review the output CSV for low-confidence matches and fix manually.
4. Run `src/apply_sentences.py` — reads updated `TheGenesisMelody_sentences.json`, finds matching `data-sentence-id` in `public/index.html`, updates `data-t-start`/`data-t-end` on the `gm-cue` span and its parent block element.
5. Update `GM_SECTIONS` `start_at` values in the inline `<script>` of `index.html` to match heading sentence timestamps.

---

## HTML structure notes

- `public/index.html` uses Google Doc exported CSS classes (`c20`, `c24`, `c81`, etc.) — don't rename them.
- Scripture passages are visually wrapped in `.scripture-block` cards by JavaScript at page load.
- The sidebar TOC uses clean slug IDs (e.g., `#summary`, `#background`).
- `gm-cue` spans drive sentence-level read-along highlighting via `public/scripts/audio-highlight.js`.
- Some block elements (especially inside tables) carry `data-t-start`/`data-t-end` directly on the `<p>` or heading tag in addition to the inner `gm-cue` span — both must be kept in sync.
